Example of LLM decision module's reasoning

Take the "rear_car" in the "Swerve" task as an example. Following the script outlined in the following figure , the agent maintains its speed while cruising on the highway. Once the ''front_car'' decelerates below 5 m/s, the agent immediately changes lanes to the right. To achieve this, we encode the sub-script and the state of the ''front_car'' in the user prompt and query the integrated LLM. The LLM automatically evaluates whether the termination condition has been met based on the state of the ''front_car'' and makes decisions according to the current action specified in the script.

Below is a complete process that demonstrates the automatically generated script for this task and the reasoning and decision-making flow of the LLM, including the original output generated during the experiment.

A case of script generation result. (A : Action T : Termination Condition R : Reason)

System prompt

The System prompt ensures that LLM consistently follows a structured approach: receiving input from the user, evaluating conditions, and making decisions based on the most current data. Every 0.5 seconds, the user provides updated information to the LLM, enabling it to process the data and determine the agent's next action in the sequence.

User prompt before front_car decelerates

This User prompt adheres to the instructions outlined in the system prompt, providing the necessary information: the action and termination condition of each step, the status of the previous step, and the current environmental data (such as the positions and speeds of the agent and other vehicles). At this point, the agent's last step was is Step 1, and the current speed of the front car is 5.81 m/s.

LLM reasoning before front_car decelerates

The LLM reasoning stage evaluates whether the previous step has been completed based on the user prompt. At this time, the LLM confirms that the front car’s speed has not yet dropped below 5 m/s, indicating that the agent should continue executing Step 1.

LLM decision before front_car decelerates

Following the reasoning, the LLM decision module generates specific behavioral instructions, including lane change direction, lane change delay, and target speed. These instructions guide the agent in executing the corresponding actions. Since the front car has not decelerated yet, the agent should continue with Step 1, maintaining a speed of 6 m/s and staying in the current lane.

User prompt after front_car decelerates

This User prompt presents updated information at a new time stamp, formatted similarly to the user prompt before the front car decelerated. At this moment, the last step of the agent is still Step 1, and the current speed of the front car is now 4.65 m/s.

LLM reasoning after front_car decelerates

At the new time stamp, the LLM reasoning stage reassesses whether the previous step has been completed based on the updated user prompt. The LLM confirms that the front car’s speed is now below 5 m/s. Therefore, the agent should proceed with the next step: lane change.

LLM decision after front_car decelerates

Following the reasoning, the LLM decision module generates the corresponding behavioral instructions. With the front car’s deceleration confirmed, the LLM decides to execute Step 2. The agent is then instructed to change lanes to the right with a 0.1s delay and continue at a speed of 6 m/s.
